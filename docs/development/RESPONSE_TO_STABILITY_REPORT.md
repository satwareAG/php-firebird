# Response to Extension Stability Report

**Date:** 2025-11-28
**To:** Doctrine Firebird Driver Team
**From:** PHP Firebird Extension Maintainers

## 1. Investigation Summary

We have investigated the critical findings reported in `EXTENSION_STABILITY_REPORT.md`.

### 1.1. `var_export` returns `NULL`
- **Status:** Confirmed, WontFix (Short Term) / Planned (Long Term)
- **Analysis:** Validated via `tests/repro_var_export_bug.phpt`. The output is `NULL` because the extension uses standard PHP/Zend Resources (`zend_register_list_destructors_ex`).
- **Context:** Standard PHP resources (e.g., `fopen` streams) also return `NULL` for `var_export`. This is standard PHP behavior, not a specific bug in this extension.
- **Path Forward:** Addressing this requires a major refactor to migrate all Resources to Opaque Objects (PHP 8.1+). This is planned for specific components but is a significant architectural change. For now, rely on `var_dump` or check `is_resource`.

### 1.2. Segmentation Faults on Cleanup
- **Status:** Partially Reproduced (Warning instead of Crash)
- **Analysis:** Test `tests/repro_segfault_blob.phpt` attempted to trigger the crash across PHP 8.1 and 8.3.
- **Result:** We observed a PHP Warning during shutdown: `Warning: PHP Request Shutdown: You can lose data. Close any blob...` on both PHP 8.1 and 8.3. We did not observe a Segfault (Exit 139) in our Docker CI environment.
- **Implication:** The extension appears to have check mechanisms preventing the crash in simple cases, converting it to a warning. However, we acknowledge the risk of race conditions in complex object graphs reported by the driver team.
- **Action:** We will review `ibase_blobs.c` resource destructors to ensure they handle invalidated links gracefully.

### 1.3. `fbird_commit_ret` Invalidates Cursors
- **Status:** Confirmed (Upstream Behavior)
- **Analysis:** This behavior stems from the underlying Firebird `isc_commit_retaining` API, which invalidates cursors by design.
- **Action:** We cannot change Firebird's transactional model. We will update documentation to explicitly warn about cursor invalidation on commit-retaining. Drivers must fetch fully before committing.

## 2. Next Steps for Extension Team

1.  **Documentation:** Update `fbird_commit_ret` documentation.
2.  **Safety Review:** Audit `ibase_blobs.c` for double-free protections.
3.  **Roadmap:** Prioritize Migration to Objects for PHP 8.4+ roadmap to solve `var_export` and provide better object lifecycles.
