# v10.6.0 Release CI Debugging - Musl/macOS/Windows

**Date**: 2026-04-01
**Context**: 14 rounds of CI debugging across release-linux.yml, release-macos.yml, release-windows.yml

## Key Findings

### 1. BusyBox grep lacks PCRE (`-P` flag)

- **Environment**: `quay.io/pypa/musllinux_1_2_x86_64` containers (Alpine-based)
- **Symptom**: `grep -oP` fails silently or errors in musl containers
- **Fix**: Replace `grep -oP 'pattern'` with POSIX `sed -n 's/.*pattern.*/\1/p'`
- **Affected**: ICU version detection in `build-precompiled.sh`

### 2. PHP JIT incompatible with musl-libc (ZTS builds)

- **Symptom**: `@TLSGD operator requires '%rdi'` compilation error
- **Root cause**: PHP opcache JIT uses Thread-Local Storage patterns incompatible with musl's TLS implementation
- **Fix**: Add `--disable-opcache-jit` to PHP `./configure` for musl builds
- **Note**: JIT is not needed for extension compilation; only opcache module is affected

### 3. SIGPIPE (exit 141) from verbose CI output

- **Symptom**: Builds exit 141 (128+13 = SIGPIPE) under `set -euo pipefail`
- **Root cause**: `tar -czvf`, `ls -la`, and `ldd` produce large stdout that fills CI log buffer; when the reader disconnects, SIGPIPE kills the script
- **Fix**:
  - `tar -czvf` -> `tar -czf` (remove verbose flag)
  - `ls -la` -> `ls -1 | head -40`
  - `ldd output` -> `| head -30`
- **Rule**: In CI scripts with `set -eo pipefail`, always cap verbose output with `| head -N`

### 4. musl `ldd` loads binaries (unlike glibc ldd)

- **Symptom**: `ldd` on musl actually executes the binary via dynamic linker, causing symbol resolution errors
- **Workaround**: Use `readelf -d` or `objdump -p` instead of `ldd` for dependency inspection in musl containers

### 5. macOS APFS case-insensitivity conflicts with `VERSION` file

- **Symptom**: C++ `#include <version>` resolves to our `VERSION` file on case-insensitive APFS
- **Fix**: Workaround in macOS release workflow to handle the collision

### 6. Firebird SDK `.pkg` extraction layout variance

- **Symptom**: `pkgutil --expand` extracts `Payload/Versions/A/` not `Firebird.framework/`
- **Fix**: Detect both bare framework and standard framework layouts in `extract-firebird-macos.sh`

## Remaining Issue

All 8 musl x86_64 builds fail at "Create Bundle" step - rerun submitted. If persistent, need to inspect the actual musl build logs for the specific failure (may be a different issue from SIGPIPE).

## Patterns for Future Releases

1. Always test musl builds locally before tagging: `docker run --rm -v $PWD:/ext quay.io/pypa/musllinux_1_2_x86_64 bash /ext/scripts/build-precompiled.sh`
2. Use POSIX-only tools in container scripts (no `grep -P`, no bash-only features in Alpine)
3. Cap all verbose output in CI scripts to prevent SIGPIPE
4. Test macOS builds on arm64 first (macos-14), x86_64 runners are deprecated (macos-13)
