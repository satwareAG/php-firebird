# v10.1.0 and v10.2.0 Roadmap

**Date**: 2026-03-30
**Author**: satware AG / Jane Alesi
**Status**: COMPLETED

## Summary

Two-milestone roadmap to make php-firebird "rock stable, state of the art" for PHP 8.2-8.5.
Both milestones focus on eliminating the last legacy bridge code and fixing the server-side
RAM leak that was discovered in v10.0.1 and temporarily reverted in v10.0.2.

## v10.1.0 - Statement Cleanup + ISC_TEB Removal

**Issues**: #139, #140
**Focus**: Fix the server RAM leak for FB 4+/5+ users via compile-time version gating.

| Issue | Title | File | LOC |
|-------|-------|------|-----|
| #139 | FB version-gated IStatement::free() / IResultSet::close() | src/cpp/fb_statement.hpp | ~40 |
| #140 | Remove ISC_TEB dead code from fbird_transaction.c | fbird_transaction.c | ~10 |

### Key Technical Decision

Use `#if FB_API_VER >= 40` compile-time gating rather than runtime detection. This is the
correct approach because:

1. The CI matrix compiles once per (PHP version x FB client version)
2. FB 3.0 client jobs compile with FB_API_VER=30 - they get safe `release()` paths
3. FB 4.0/5.0 client jobs compile with FB_API_VER=40/50 - they get `free()`/`close()`
4. Precompiled bundles use FB 5.0 client (FB_API_VER=50), which connects to any server
   version via wire protocol (FB 5.0 client handles FB 3.0 server connections gracefully)

## Branch Strategy

batches:
