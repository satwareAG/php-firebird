# Implementation Plan: v10.3.0 — Repo Hygiene + CI/CD Pipeline Optimization

**Status: COMPLETED**

## [Overview]

v10.3.0 combines dead-code removal with comprehensive CI/CD pipeline improvements to make
the pipeline faster, more secure, and more robust for PHP 8.2–8.5 × Firebird 3.0/4.0/5.0.

This release has zero PHP API changes — it is purely a developer-experience and
infrastructure improvement release. The goals are:

1. **Repo hygiene**: Remove dead legacy files (`firebird_legacy_wrappers.c/h`, ISC_TEB compat
   struct in `php_fbird_includes.h`) and gitignore dev-only scratch files (`patch*.php`,
   `restore.php`, `run_events_test.php`, `test_error.php`, `.env.bak`).

2. **CI/CD performance**: Add Firebird client caching to `coverage.yml` and `sanitizers.yml`
   (currently they re-download 50MB+ every run). Add path-filter triggers to avoid unnecessary
   workflow runs on documentation-only changes.

3. **CI/CD correctness**: Add `concurrency` groups to `coverage.yml`, `code-quality.yml`, and
   `codeql.yml` so duplicate runs are auto-cancelled.

4. **CI/CD security**: Add `permissions: read-all` at workflow level + scoped write permissions
   per job to all workflows. Pin all action references to immutable SHAs.

5. **Explicit runner versions**: Replace `ubuntu-latest` with `ubuntu-24.04` in all workflows
   for reproducible builds.

## Security Notes

- Permissions default: `permissions: read-all` at workflow level prevents accidental
  credential leakage. Write permissions granted only where needed:
  - `contents: write` for release jobs (asset upload)
  - `security-events: write` for CodeQL
  - `packages: read` for reading container registry
- SHA pinning prevents supply-chain attacks via tag rewriting
- Concurrency with `cancel-in-progress: true` prevents ghost jobs consuming runner minutes
