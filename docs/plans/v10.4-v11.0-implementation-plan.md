# v10.4.0 - v11.0 Implementation Plan

> **Status: COMPLETE** | Created: 2026-03-31 | Completed: 2026-04-09 | Released: v11.0.0

## Overview

Dependency-optimized implementation plan for 20 open issues across 5 milestones.
All v10.3.x work is complete (v10.0.0 through v10.3.9 shipped). This plan covers
the remaining roadmap from supply chain hardening through the v11.0 modernization
milestone.

## Milestone 3: v10.5.0 - Testing Improvements ✅ COMPLETE

**Due: 2026-07-31** | **Spec:** `specs/spec-v10.5-testing.md` | **4 issues**

Issues ordered by impact (highest test reliability gain first):

| Order | Issue | Title | Effort | Dependencies |
|-------|-------|-------|--------|--------------|
| 1 | #168 | Add --CLEAN-- sections to all .phpt tests | 6-10h | None (70+ test files) |
| 2 | #170 | Create fuzz dictionary for Firebird SQL | 2-4h | None (enhances existing fuzz/) |
| 3 | #169 | Add TSan (Thread Sanitizer) for ZTS builds | 4-6h | None (new CI workflow job) |
| 4 | #171 | Add macOS CI job (build-only) | 4-8h | None (prereq for v10.6.0 #174) |

### Implementation Notes

- **#168**: Add `--CLEAN--` section to every `.phpt` that creates tables, databases, or temp files. This is the highest-value change - prevents inter-test contamination that causes flaky CI.
- **#170**: Create `fuzz/dictionary.txt` with Firebird SQL keywords, data types, system table names. Feed to existing `fuzz/run.php` infrastructure.
- **#169**: Add ZTS build matrix entry with `-fsanitize=thread`. Requires separate Firebird client build or suppression file for known FB client races.
- **#171**: Add `macos-latest` job to CI workflow. Build-only (no Firebird server on macOS runners). This validates compilation and is a gate for v10.6.0 macOS precompiled builds.

## Milestone 5: v11.0 - Modernization

**Due: 2026-12-31** | **Spec:** `specs/spec-v11-modernization.md` | **5 issues**

Issues ordered by risk (quick cleanups first, breaking changes last):

| Order | Issue | Title | Effort | Dependencies |
|-------|-------|-------|--------|--------------|
| 1 | #178 | Remove dead FB_API_VER < 30 code paths | 2-4h | None (dead code removal) |
| 2 | #179 | Remove legacy gds32_ms fallback from config.w32 | 1-2h | None (Windows cleanup) |
| 3 | #175 | Migrate 84 procedural arginfo to typed returns | 8-16h | None (prep for #176) |
| 4 | #177 | Replace call_user_function() with direct C calls | 8-12h | None (OOP layer perf) |
| 5 | #176 | Resource-to-object migration for Layer 1 | 16-24h | #175 (typed signatures first) |

### Implementation Notes

- **#178**: Search for `#if FB_API_VER < 30` / `#ifdef FB_API_VER` guards. FB 3.0 is our minimum since v10.0.0 - all `< 30` paths are dead.
- **#179**: Remove `gds32_ms.lib` fallback from `config.w32`. Modern Firebird Windows uses `fbclient_ms.lib` only.
- **#175**: Replace `ZEND_BEGIN_ARG_INFO_EX` with `ZEND_BEGIN_ARG_WITH_RETURN_*` macros for all 84 procedural functions. This adds return type info visible to `ReflectionFunction`.
- **#177**: Replace `call_user_function()` calls in `fbird_classes.c` with direct C function calls. Eliminates userland call overhead in OOP wrapper.
- **#176**: **BREAKING CHANGE**. Convert `fbird_connect()`, `fbird_query()`, `fbird_trans()` etc. from returning resources to returning opaque objects. Requires major version bump (v11.0). Must update all stubs. Largest single change in the entire roadmap.
